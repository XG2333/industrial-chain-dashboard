# 看板图表与产业接入规范

本文档记录本项目图表组件的统一渲染规则，以及新增产业看板时的接入步骤。后续新增产业时，应先阅读本文档，避免重复出现 y 轴、背景、数据加载等问题。

## 0. 总览页数据源过滤

- 总览 Tab（整产业全量数据）只画 Excel 目录**最后一列"二次筛选是否保留"**为"是"的指标（锂电当前 199 条；"是否选中"列 1300+ 条为另一套筛选，不作总览依据）。
- 后端：`/api/battery/excel/meta` 支持 `selected_only` 参数（`ExcelRequest`），为 true 时只返回 `final_selected`（"二次筛选是否保留"）为真的图表（数据源层面过滤）。
- 前端：总览请求传 `selected_only: true`，并强制按 `finalSelected` 过滤（隐藏"显示全部指标"切换按钮）；板块 Tab 保留原"是否选中"（selected）切换。
- 排序、归组、行排布等规则不变。

## 0. 配色体系（shadcn admin）

- CSS token：`frontend/src/index.css` 使用 shadcn/ui 官方 OKLCH 变量（`--background/--foreground/--card/--primary/--muted/--border/--ring` 等），浅色 + `.dark` 深色双主题。
- 图表色板：`--chart-1..8`（shadcn chart 色），`chartTheme.ts` 的 palette 用其 hex 近似值（浅色/深色两套）。
- 年份颜色：`chartColors.ts` 对齐 chart 色板（2022 起按 chart-1..5，2027 用 chart-6），2026/2027 不再重复红色。
- 页面背景统一 `bg-muted`（不再硬编码 `#f1f5f9`）。
- 业务语义色（红涨绿跌等）保留在 `frontend/src/theme/dashboardTokens.css` 的 `--dashboard-*`，不随主题改动。

## 0. 频率判断兜底

- 数据目录的 `freq` 标记可能与实际数据不符（如日本海关标 daily 但数据实际为月度）。
- SeasonalChart 按**相邻日期平均间隔**判断（与历史长度无关）：≤3 天 → 日度（366 日轴）；3~14 天 → 周度（53 格周轴 + 同周合并）；>14 天或单点 → 月度渲染（折线 + 12 月横轴）。不再用"年化点数"口径（短历史周度数据年化点数 ≤13 会被误判为月度）。
- 真日度数据（平均间隔 ≈1 天）与周频（≈7 天）不受影响。数据侧修正后需重启服务重建缓存（缓存按 Excel mtime 重建）。

## 0. 产业新闻行业过滤

- `/api/overview/news?industry={lithium|tin|silicon}` 按行业关键词表（`server.py NEWS_KEYWORDS`）过滤东财近 7 天快讯（标题或摘要命中任一关键词即保留，按天分组每天最多 2 条，取前 20）。
- 各行业独立词表：锂电（含光伏硅词，历史行为）；锡（沪锡/焊料/镀锡板/马口铁/锡锭/锡矿/锡精矿/锡材/锡价/锡业/铅蓄电池/铅酸电池）；硅（多晶硅/单晶硅/硅片/硅料/有机硅/工业硅/光伏/电池片/组件/硅价/硅业/硅烷/隆基/通威/合盛硅业/晶澳）。
- 前端：`Battery.tsx`（锂电）不传参数；`Metals.tsx` / `Silicon.tsx` 分别传 `industry=tin` / `industry=silicon`。

## 1. 图表组件

所有产业看板共用同一套图表组件，位于：

- `frontend/src/components/charts/SeasonalChart.tsx`
- `frontend/src/components/charts/YearlyChart.tsx`
- `frontend/src/components/charts/TrendChart.tsx`
- `frontend/src/components/charts/FinChart.tsx`

页面文件：

- 锡看板：`frontend/src/pages/Metals.tsx`
- 硅看板：`frontend/src/pages/Silicon.tsx`

修改图表时只需修改共享组件，锡、硅以及未来新增产业都会同时生效。

- 指标大类固定顺序：价格、成本利润、库存、供给、需求、进出口、平衡、其他；数据中的“供给/供应”统一排在需求之前。
- 价格大类下“成交量、持仓、成交持仓比”按同一指标归组为一行；指标类别导航统一显示为“成交持仓”按钮，位置排在价格大类最后一个子类。
- “个股标的”股票池由 `多skill联动/output/个股标的_*.xlsx` 驱动，前端不再维护固定股票代码；Excel 缺失时对应板块股票池为空。
- “个股标的”的核心标的池、行情数据、财务数据中，每只股票右侧显示 Excel 的“所属环节”。
- 日频/周频/月频季节图 X 轴统一显示 `1~12` 数字月份标签，12 个月份全部完整显示，不显示“月”字。

## 2. 统一图表规则

### 2.1 白色背景

每张图都固定使用白色背景，不再透明：

- 外层容器 `backgroundColor: "#fff"`
- ECharts 容器 `backgroundColor: "#fff"`
- ECharts option 顶层 `backgroundColor: "#fff"`

### 2.2 y 轴范围

y 轴范围不再依赖 ECharts 默认值，而是根据当前指标数据计算：

1. 先通过 `cleanAxisValues` 过滤明显占位异常值：
   - 仅过滤 Excel 中常见的占位值，如 `9998`、`9999`、`99998`、`99999` 等
   - 其他真实历史极值全部保留，不能从 y 轴范围中移除
   - 不要使用 IQR：当数据集中在同一个值时 IQR 为 0，会把真实最大/最小值误删
2. 使用清洗后的数据计算 `min` 和 `max`
3. 上下留白为范围的 5%（最小为 0.05；下限为绝对值，防止小数值指标如情绪因子 2.6~3.5 被撑成 2~4）
4. 非负指标下界钳制为不小于 0
5. 非正指标上界钳制为不大于 0
6. 计算出的 `axisMin`/`axisMax` 直接应用到 yAxis 的 `min`/`max`，不依赖 ECharts 自动范围，保证数据在绘图区内合理分布、刻度等距

示例：持仓量最小值为 0 时，y 轴从 0 开始，不会出现 `-3.7万`、`-8156` 这类错误负刻度。

所有指标统一保留真实极值，只移除明确占位值；任何真实数据点都不允许超出 y 轴范围。

### 2.3 y 轴刻度等值

- 所有 y 轴设置 `splitNumber: 5`
- ECharts 会自动生成整齐、等差的刻度，如 `100、150、200`

### 2.4 大数格式化

- y 轴刻度标签：完整显示数字并加千分位（如 `8,000`、`150,000`），不缩放、不带量级单位（不显示“千/万/亿”字）；绝对值 <10 且非整数时保留 1 位小数（避免小范围指标整数标签重复）。
- 隐藏 y 轴最低/最高刻度标签（`axisLabel.showMinLabel/showMaxLabel: false`）。
- 季节图 x 轴不显示“月”字。
- 实现：`axisScaleFor(maxAbs)` + `formatAxisValue(value, divisor)`（`chartFormat.ts`），所有图表组件统一使用。
- 避免出现 `0.000`、科学计数法等错误刻度。

### 2.5 行业数据分组规则

- 行业数据按 Excel 目录中的 `大类`（major）和 `子类`（sub）字段分组展示
- 前端不得硬编码拆分某个大类/子类，例如“进出口 / 净出口”必须完全跟随 Excel
- 如果 Excel 把“进出口”合并为一个子类，看板就显示一个大类、一个子类；如果 Excel 拆成多个子类，看板自动显示多个子类
- 修改 Excel 结构后，只需重启服务并强制刷新页面，无需修改前端分组代码
- 后端必须向前端返回 `catalogOrder`（与 `catalog_order` 同值），前端以该字段作为唯一业务排序依据
- 大类、子类、频率和 Display Block 顺序均由 `min(catalog_order)` 决定，前端不再使用固定业务排序表覆盖 Excel 顺序
- 图表排序、归组和行排布细节见 `docs/排序规则.md`

### 2.6 季节图月份标签

- 日频、周频、月频季节图 X 轴统一显示月份数字标签 `1~12`（不含“月”字），12 个月份全部完整显示。
- 必须强制保留 12 月标签，禁止使用 `hideOverlap` 把首尾月份吞掉。
- 日频图通过显式月份日序渲染标签（366 日轴，每月中点）；**周频图按年内连续周序号渲染（周一为一周开始、跨月续排，共 53 格）**，月份标签按每 4 周（≈1 月）显示一次；月频图通过显式 `interval: 0` 显示全部标签。
- 月份标签以 12 月收尾，避免窄卡片下出现只有 11 月没有 12 月的情况。

### 2.7 年份图例与绘图区间距

- 年份标签通用规则：**所有年份必须完全显示在同一行**。实现为 HTML 自定义年份行（色块 + 年份文字，flex nowrap）+ CSS `transform: scale()` 等比压缩——先按自然宽度渲染，超宽时计算 `scale = 可用宽 / 自然宽`，物理上不可能换行（不依赖 ECharts legend 自动布局，不依赖字体宽度估算）。
- ECharts legend 已禁用（`legend.show: false`），年份行位于绘图区上方（`grid.top: 34`）。
- 绘图区 `grid.top`：年份 ≤9 时为 `34`，>9 时回退 `46`（预防极端年份数换行）。
- 折线最高点不得进入年份图例区域，不允许折线与年份文字重叠。
- 图表容器高度自适应：卡片内由 `flex-1` 填满剩余空间，无父高度时 `minHeight: 140` 兜底；减少固定宽高比造成的空白。

### 2.8 图表尺寸自适应

- 图表组件容器 `height: 100%`；`LazyChartCard` 内图表区使用固定长高比 `aspectRatio: 1.73`（与五张图一行的比例一致），1/2/3/4 张行的图按宽度等比放大，长高比统一。
- 页面内直接使用图表组件的容器（无 flex 高度）时，`minHeight: 140` 兜底保证图表可见。

### 2.9 图表行列数

- 图表行按行内图数决定列数（即单图宽度）：5 张 -> 1/5 页面宽；4 张 -> 1/4 页面宽；3/2/1 张 -> 1/3 页面宽。
- 实现：`chartRowGridClass(count)`（`frontend/src/components/layout/chartRowGrid.ts`），`IndustryDataScheme1` / `IndustryDataScheme2` 共用；类名必须完整写在源码中（Tailwind JIT 扫描），禁止动态拼接。

### 2.10 绘图区留白

- `grid` 留白紧凑：单轴图表 `left: 0, right: 6, top: 6-26, bottom: 12-16`，双轴图表（FinChart）`left: 2`；y 轴数值标签 `margin: 1`（数值几乎贴轴），配合 `containLabel: true` 由 ECharts 按标签实际宽度自动扩展，将 y 轴数值与绘图区的空白压缩到极限。
- **图表卡片容器左侧 padding**（y 轴数值左侧到卡片边框的空白）：`LazyChartCard` 容器 `pl-1 pr-3 pt-3 pb-3`（左侧 4px，其余 12px）；个股详情图表容器（Silicon/Metals 行情与财务卡片）`pl-1 pr-2 pt-2 pb-2`（左侧 4px，其余 8px）。

### 2.11 周度数据展示规则（长期方案）

部分周度指标在数据源中每周有**两个日期**（如 SMM 每周四+周五各一条，见"碳酸锂样本库存/锂辉石系列"等 11 个指标），按周分组必然落在同一周格。为避免"一个月对应好几个数据点"的同格双值重叠，周频图统一执行：

1. **X 轴 = 年内连续周序号**（周一为一周开始、跨月续排，53 格/年），不用"月内均分周位置"（旧 60 格方案在 5 周月会挤压溢出，且无法表达跨月周的连续性）。
2. **同周多点合并**：按 `(年, 周序号)` 去重，取该周**最后一条**（数据按日期降序，首个即最新），保证每周一格一点。
3. 月份标签按每 4 周（≈1 月）显示一次，仍以 12 月收尾。
4. Tooltip 月份换算与 X 轴标签同源（`Math.min(12, floor(周格/4) + 1)`），yoy/累计 yoy 取该月最后一条（展示层近似，不修改数据）。
5. 实现位置：`SeasonalChart.tsx` 的 `weekIndex()` 与周度合并逻辑。
6. **频率判定统一按相邻日期平均间隔**（与历史长度无关）：平均间隔 ≤3 天 → 日度（366 日轴）；3~14 天 → 周度（53 格周轴 + 同周合并）；>14 天或单点 → 月度（12 月格）。不再用"年化点数"口径——短历史周度数据（如氢氧化锂样本库存仅 13 点/3 个月，年化点数恰好 ≤13）按旧口径会误落月度渲染，导致同月多周点重叠；间隔判定同时修复目录 `freq` 标记错误（如"磷酸铁锂库存: 铁锂厂"标题周度但字段标 monthly）。

> 数据侧长期目标：多skill联动 workflow 生成周度 sheet 时只写每周最后一个有效日期，从源头消除双值（届时 2 步合并成为幂等兜底）。

## 3. 后端数据加载通用规则

### 3.1 Excel 结构要求

每个产业数据文件必须满足：

- 第一个 sheet 为 `目录`，作为指标目录
- 目录中每行包含：sheet 名、列号、指标名、单位、板块、大类、子类、置信度、是否选中等字段
- 后续 sheet 为指标数据表，前三行分别为指标名、单位、频率，第四行开始为日期和数据

### 3.2 通用加载函数

`server.py` 中 `_load_excel_workbook(filepath, prefix)` 是通用加载函数，只传文件路径和英文前缀，不依赖具体产业名。

`_load_all_workbooks()` 负责加载所有产业并把图表按英文 key 注册到：

- `_SOURCE_CHARTS`：`"tin"` / `"silicon"` → 图表列表
- `_SOURCE_SECTORS`：`"tin"` / `"silicon"` → 板块集合

### 3.3 数据就绪与缓存

- 启动时在后台线程加载 Excel
- 接口请求时会等待 `_DATA_LOAD_EVENT`，确保数据加载完成后再返回
- 空结果不写入缓存，避免数据加载完成前把“0 条”错误缓存住

## 4. 新增产业看板步骤

### 4.1 后端

1. 把新产业 Excel 放入 `data/` 目录
2. 在 `server.py` 增加文件路径，例如：

```python
NEW_WORKBOOK_PATH = PROJECT_ROOT / "data" / "新产业数据_processed.xlsx"
```

3. 在 `_load_all_workbooks()` 中加载并注册：

```python
new_charts, new_sectors = _load_excel_workbook(NEW_WORKBOOK_PATH, "newindustry")
if new_charts is not None:
    _SOURCE_CHARTS["newindustry"] = new_charts
    _SOURCE_SECTORS["newindustry"] = new_sectors
    all_charts.extend(new_charts)
```

4. 在 `_resolve_source()` 的硬编码集合中加入新产业板块，并把中文产业名映射到英文 key：

```python
TAB_TO_SOURCE = {"锡": "tin", "硅": "silicon", "新产业": "newindustry"}
NEW_SECTORS = {"新板块1", "新板块2"}
```

5. 前端请求时传 `dataset: "newindustry"`（英文 key），不要传中文 key。

### 4.2 前端

1. 复制 `Silicon.tsx` 为 `NewIndustry.tsx`
2. 修改：
   - 页面标题
   - `TABS` 和 `SUB_SECTORS` 为新产业板块
   - `DEFAULT_STOCKS` 为新产业股票
   - `dataset: "silicon"` 改为 `dataset: "newindustry"`
   - localStorage key 从 `si_` 改为新前缀
3. 在 `frontend/src/router.tsx` 增加路由
4. 在 `frontend/src/components/layout/Layout.tsx` 增加侧边栏导航

### 4.3 图表组件

新增产业不需要修改图表组件。如果后续要调整图表显示规则，只改共享组件即可。

## 5. 常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| y 轴出现 -3.7万 等负刻度 | y 轴下界留白过大且未钳制 | 检查 `axisMin` 非负钳制逻辑 |
| y 轴显示 9999/7158 | 数据含占位异常值 | 确认 `cleanAxisValues` IQR 过滤生效 |
| y 轴显示 0.000 | 大数未格式化 | 确认 `formatYAxis` 已挂到 axisLabel |
| 真实极值超出 y 轴 / y 轴最高值变小 | 异常值过滤误删真实极值 | 只过滤明确占位值，保留所有真实 min/max |
| 进出口仍显示进口/出口/净出口三个子类 | 前端未按指标名称归组 | 按第 7 节“进出口大类显示规则”处理 |
| 子板块显示 0 条 | 数据未就绪或空结果被缓存 | 检查 `_DATA_LOAD_EVENT` 与空结果不缓存逻辑 |
| 新产业板块取不到数据 | dataset key 或板块名不匹配 | 检查 `_SOURCE_SECTORS` 与前端 `SUB_SECTORS` 是否一致 |

## 7. 进出口大类显示规则

- “进出口”大类不按 Excel 子类拆分为“进口、出口、净出口”三个小标题。
- 前端按指标名称重新归组：同一产品的进口、出口、净出口图放在同一行；归组 key 由 `industryGroups.tradeGroupKey` 生成（产品 + 地区/国别维度 + 频率 + 量/额），行排布与导航分组共用，不依赖数据侧 composite 标签（净出口标签 key 与进口/出口不一致）。
- 每行上方显示小标题，格式为“指标名称 + 进出口与净出口图”。
- 行内顺序固定为：进口、出口、净出口；由 `groupChartRows` 组内按 sub 排序实现（成交持仓行内为：成交量、成交、持仓、持仓量、成交持仓比），不依赖数据目录顺序。
- 指标行按名称排序。
- 指标类别导航中，“进出口”大类不展示各指标名称子类按钮，只保留一个“进出口”按钮，点击定位到整个进出口板块。
- 数据文件不改动，归组由前端标题归一化逻辑完成；新增进出口指标时，标题中的进口/出口/净出口命名应保持可识别：净出口标题建议带海关前缀（如“中国海关 碳酸锂净出口”），否则无法与带前缀的进口/出口（如“中国海关: 碳酸锂进口量”）自动对齐。

## 8. Excel 数据文件规则

- Excel 中涉及公式计算的列，在保存数据文件前必须保留或固化计算结果值。
- 推荐在 Excel 中完成计算后，将公式列“复制 -> 粘贴为值”再保存，确保 `.xlsx` 文件中包含缓存计算结果。
- 后端已对“单元格相减/相加”等简单公式做兜底计算；复杂公式仍应保存计算结果值，避免图表空白。
- 不要依赖后端读取时实时计算 Excel 公式；`openpyxl`/`pandas` 读取公式列时，如果文件没有缓存结果，会读到空值，导致前端图表空白。
- 更新 Excel 后，按 `stop.bat` + `start.bat` 重启服务，让后端按文件修改时间重建数据缓存。

## 9. 规则同步约定

每次修改看板规则、图表规则、排序规则或对应 Python 脚本后，必须同步更新以下文件：

- `docs/排序规则.md`：当前项目看板排序、归组和行排布规则。
- `<local-documents>/多skill联动/排序规则.md`：Skill4 的排序规则依据。
- `<local-documents>/多skill联动/skills/dashboard-data-sorter/SKILL.md` 与 `README.md`：Skill4 行为说明。

如果本次修改还影响数据计算规则，还需同步 `<local-documents>/多skill联动/rules/` 下对应 md。规则 md 与实际执行脚本必须在同一轮修改中保持一致。
